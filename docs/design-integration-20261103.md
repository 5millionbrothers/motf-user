사장님 앱의 운영 기준은 `public/owner/`입니다. 미래 이전용 `src/`에 기능을 중복 구현하지 않았습니다.
이용자 홈페이지의 기존 경로별 HTML 30개도 루트와 동기화했습니다. 깊은 주소로 직접 들어가도 같은 헤더와 스타일을 사용합니다.
루트 HTML을 이후 수정하면 `node scripts/sync-route-shells.mjs`로 동기화합니다.

## 화면 적용

- 모든 페이지 콘텐츠 폭 1280px, 공통 헤더, 흰색 배경·기존 올리브 컬러·기존 로고.
- 홈 순서: 캐치프레이즈/실제 숙소 검색 → 가로 배너 → 숙소 추천 → 장보기 추천 → 계산기 → 기존 카드뉴스/PICK → 내 MT 연결.
- 최종 시안에서 삭제한 3D 모션·중복 빠른 메뉴는 넣지 않았습니다.
- 숙소·장보기의 기존 세부 정보, 예약, 달력, 배송 안내, 상품 옵션, 장바구니는 유지했습니다.
- 모바일은 홈/숙소/장보기/모리지널/내 MT 하단 탭, 마이는 우측 상단입니다. 커뮤니티는 홈 콘텐츠와 각 페이지 버튼에서 진입합니다.
- 모바일 숙소 검색은 동일한 원본 검색 폼을 팝업에 옮깁니다. 별도 모의 검색을 만들지 않았습니다.
- 일반 찜 진입 버튼을 내 MT 담기로 통일하되 기존 저장된 찜 기록을 삭제하지 않았습니다.

## 계산기

홈 계산기의 숙소·장보기 비용은 인원/예산에 따른 배분 예시이며 실제 상품 가격이 아닙니다. 화면에 이를 표시합니다.
1/10/100만원 단위 조정, 슬라이더, 인원·날짜, 수동 기타 비용을 사용할 수 있습니다.
숙소/장보기 담기와 이어가기는 기존 내 MT 생성·선택으로 연결됩니다.
새 MT에는 인원·날짜·전체 예산과 직접 입력한 기타 비용만 저장합니다. 예시 숙소·장보기 비용은 저장하지 않습니다.
기존 MT를 선택하면 홈 예산으로 기존 프로젝트를 덮어쓰지 않습니다.
실제 내 MT의 기타 비용은 `mt_project_items`에 저장되고 기존 삭제 함수/RLS를 사용합니다.

## 운영자 배너 관리

1. 운영자 로그인 후 `이벤트·배너·콘텐츠 → 메인 배너`를 엽니다.
2. 이미지 업로드 또는 URL, 제목·보조 문구, 이동 대상과 버튼 문구를 입력합니다.
3. 이동 대상은 내 MT/숙소/장보기/레크/MOriginal 목록·상세/외부 링크입니다. MOriginal 상세는 등록된 행사에서 선택합니다.
4. 순서는 작은 숫자부터입니다. 시작·종료를 비우면 해당 시간 제한 없이 노출됩니다. 숨기기는 데이터를 삭제하지 않습니다.
5. 첫 배너는 `내 MT 만들기` 고정입니다. 그 뒤 관리자 배너와 공개 MOriginal이 나옵니다. 같은 행사를 연결한 프로모션 배너가 있으면 행사 자동 배너는 중복하지 않습니다.
6. 등록·수정·숨기기·삭제는 기존 `homepage_cards`와 `content-media` 저장소 권한을 사용합니다. 서비스 키를 브라우저에 추가하지 않습니다.

기존 카드뉴스 탭의 프로모션과 새 메인 배너는 같은 레코드입니다. 프로모션은 이제 카드뉴스 열이 아닌 메인 배너에 표시됩니다.
열려 있는 이용자 화면은 기존 콘텐츠 갱신 주기(약 1분) 또는 탭 재활성화/새로고침으로 갱신됩니다.
이미지 위 문구가 겹치므로 가로 사진을 사용하고 제목은 짧게 작성하는 편이 좋습니다.

## 검증 범위와 남은 실환경 확인

- 기존 NICEPAY/API 자동 테스트 64개 통과: 승인·서명·금액 한도·권한·웹훅·중복 처리·환불·과거 Toss 주문 호환.
- 수동 기타 비용 어댑터 4개 테스트 통과: 프로젝트 귀속·권한·금액·실패 처리.
- 320/390/600/700/768/1024/1280/1440/1920px에서 9개 공개 경로 총 81개 레이아웃 확인.
- 실제 공개 숙소/상품 조회, 배너 행사 이동, 익명 MT 생성 로그인 유도, 모바일 검색·공판장 정보 팝업, 직접 URL 진입 확인.
- 등록된 지도 도메인 조건에서 로컬 수정 소스를 제공하는 브라우저 테스트로 실제 SDK·지도 캔버스 표시 확인. 운영에 파일을 업로드한 것은 아닙니다.
- 모의 계정/DB로 MT 생성 연결, 수동 비용만 저장, 기존 MT 보존, NICEPAY 결제 방식·start 요청·form·return·창 닫기 연결 확인.
- 운영자 배너 생성/수정/이미지 보존/순서/일정/숨김/삭제/권한을 모의 DB로 검증.

실제 인증 계정의 생성·초대·주문·글쓰기·관리자 저장과 실결제/환불은 운영 데이터에 영향을 주므로 자동으로 실행하지 않았습니다.
Vercel Preview에서 전용 테스트 계정과 NICEPAY 테스트 설정으로 이 항목을 확인한 다음 운영 배포합니다.
지도·KCP·Kakao·NICEPAY는 도메인 허용 설정을 확인해야 합니다. localhost/미등록 Preview에서는 외부 인증이 실패할 수 있으며 운영 DB 키를 바꾸는 방식으로 우회하지 않습니다.

## 적용과 되돌리기

1. 업로드 ZIP의 이용자·사장님 폴더 내용을 각각 해당 GitHub 저장소에 경로 그대로 반영합니다. 전체 폴더를 상대 저장소 안에 한 겹 더 넣지 않습니다.
2. 변경 파일만 포함되어 있으므로 원래 저장소 파일을 삭제하지 않습니다. 기존 환경변수와 SQL을 유지합니다.
3. 두 저장소를 Vercel Preview에서 먼저 확인합니다. 운영자 배너와 이용자 소스는 같은 버전으로 맞춥니다.
4. 실제 회원/결제/지도 검증 후 운영 반영합니다. 이미 등록된 MOriginal·카드·상품·예약을 다시 만들 필요가 없습니다.
5. 되돌릴 때는 이번 변경 파일만 이전 커밋 버전으로 복원합니다. 신규 테이블이 없으므로 DB rollback SQL은 필요 없습니다. 테스트로 만든 배너/MT가 있다면 별도로 정리합니다.
